Thonny tips — before coding

Getting started in Thonny

Code to add — comfort_status() function

Add this function BEFORE the web_page() function in your file

# ===== COMFORT LOGIC =====
# Temperature and humidity thresholds for Queensland conditions
def comfort_status(temp, hum):
    # Too hot OR too humid → unsafe for Elders
    if temp > 30 or hum > 70:
        return "Too Hot / Humid", "#B03A2E", "⚠️ Not recommended for session"
    # Warm or slightly humid → caution
    elif temp > 26 or hum > 60:
        return "Getting Warm", "#2B8BE0", "🌡️ Monitor closely"
    # Comfortable range
    else:
        return "Comfortable", "#2A6B45", "✅ Safe for Yarning Circle"

Wiring guide

Pushbutton (GP14)

Button legConnect to
Leg 1 (left)GP14
Leg 2 (right)3.3V
Leg 1 also10kΩ resistor → GND (pull-down)

Why pull-down?

Without a resistor connecting GP14 to GND, the pin "floats" between 0 and 1 randomly when the button isn't pressed. The 10kΩ to GND holds it at 0 (LOW) until the button connects it to 3.3V (HIGH).

Active Buzzer (GP15)

Buzzer pinConnect to
+ (longer / marked)GP15
– (shorter)GND

Active vs passive buzzer

The kit's active buzzer has its own oscillator — it makes a tone as long as power is applied. Just set the pin HIGH. A passive buzzer needs a PWM frequency from Python to make sound (Lesson 4 extension).

Code additions — hardware setup section

Add to the HARDWARE section near the top of your file

# Add these lines after your existing led and sensor setup
button = Pin(14, Pin.IN, Pin.PULL_DOWN)
buzzer = Pin(15, Pin.OUT)
buzzer.value(0)  # Start with buzzer OFF

Code additions — updated main loop

Replace your while True: loop with this updated version

# ===== MAIN LOOP =====
while True:
    try:
        # Read sensor
        sensor.measure()
        temp = sensor.temperature()
        hum  = sensor.humidity()
        
        # Get comfort status
        label, colour, message = comfort_status(temp, hum)
        
        # Buzz once (short beep) if too hot/humid
        if label == "Too Hot / Humid":
            buzzer.value(1)
            time.sleep(0.3)  # Short beep only
            buzzer.value(0)
        
        # If button is pressed, show a "reading taken" message
        if button.value() == 1:
            print("Button pressed — fresh reading: ", temp, "°C", hum, "%")
            # Short LED flash to confirm
            led.value(1); time.sleep(0.1); led.value(0)
        
        # Handle web requests
        try:
            client, addr = server.accept()
        except:
            continue

        request = client.recv(1024).decode()

        if "GET /?led=on" in request:
            led.value(1)
        elif "GET /?led=off" in request:
            led.value(0)

        response = web_page(temp, hum, led.value(), label, colour, message)
        client.send("HTTP/1.1 200 OK\r\nContent-Type: text/html\r\n\r\n")
        client.send(response)
        client.close()

    except Exception as e:
        print("Error:", e)
        buzzer.value(0)  # Always turn buzzer off on error
        time.sleep(2)

Thonny debugging techniques

Technique 1 — Read the error message

Error messages in Thonny's Shell always tell you the line number and type. Common ones:

AttributeError: 'NoneType'... → your variable is None, probably sensor failed to read
OSError: [Errno 113] → WiFi connection lost
SyntaxError: invalid syntax → missing colon, bracket or quote
IndentationError → mixed tabs and spaces (Thonny: Edit → Toggle tabs/spaces)

Technique 2 — Add print() statements

Insert print() before and after suspected problem areas to see exactly where it stops:

Debug print example — trace where sensor fails

while True:
    print("About to read sensor...")   # Add this
    try:
        sensor.measure()
        temp = sensor.temperature()
        print("Temp read:", temp)         # Add this
        hum = sensor.humidity()
        print("Hum read:", hum)          # Add this
    except Exception as e:
        print("Sensor error:", e)        # This will show what went wrong

Technique 3 — Test functions in the Shell

You don't need to run the whole program to test a function. In Thonny's Shell, type:

comfort_status(28, 55) → should return ('Comfortable', '#2A6B45', '✅ ...')
comfort_status(32, 65) → should return the "Too Hot / Humid" tuple

If the function isn't loaded yet, press Run (F5) first to load it, then Ctrl+C to stop the loop, then test in the Shell.

Common bugs — teacher demo

label, colour, message = comfort_status(temp, hum)

Extension Project Ideas Using the Full Kit

Self-directed  ·  Consult your teacher before starting these

1. Photocell (light sensor) — GP26 (ADC)

The photocell is an analogue sensor — it doesn't give 0 or 1 like a button, it gives a value from 0 to 65535 depending on light level. You need to use an ADC (Analogue-to-Digital Converter) pin.

Project idea: Add "Room Light Status" to your web page — if light is below 10,000 it shows "Room is Dark" as a prompt to turn lights on before the session.

Photocell reading

from machine import ADC

light_sensor = ADC(Pin(26))

# In your main loop:
light_val = light_sensor.read_u16()
# 0 = very dark, 65535 = very bright
print("Light level:", light_val)

2. Trimpot (variable resistor) — GP27 (ADC)

The 10kΩ trimpot with knob lets you input a variable value by turning the dial. This can act as a physical "threshold adjuster" — Aunty Leanne could turn a knob to set her preferred maximum temperature.

Project idea: Replace the hard-coded 30 threshold with a value read from the trimpot, mapped to the range 22–35°C. Display the current threshold on the web page.

Trimpot reading and mapping

pot = ADC(Pin(27))

# Map 0–65535 to 22–35°C
def read_threshold():
    raw = pot.read_u16()
    # Scale to 22–35 range
    threshold = 22 + (raw / 65535) * 13
    return round(threshold, 1)

3. Multiple LEDs — visual traffic light

Using two more 5mm LEDs from your kit (220Ω resistor each), create a traffic light system where green = comfortable, amber = warm, red = too hot. These update automatically — no web page needed.

Pins: Green LED → GP11, Amber LED → GP12, Red LED → GP10

Traffic light LED logic

led_green  = Pin(11, Pin.OUT)
led_amber  = Pin(12, Pin.OUT)
led_red    = Pin(10, Pin.OUT)

def update_leds(label):
    led_green.value(1 if label == "Comfortable" else 0)
    led_amber.value(1 if label == "Getting Warm" else 0)
    led_red.value(1 if label == "Too Hot / Humid" else 0)

4. Reading history log

Store the last 5 readings in a Python list and display them as a table on the web page. This gives community staff a sense of whether conditions are improving or getting worse.

Note: The Pico W only has 264KB of RAM, so keep your history list small (max 20 readings).

History log in Python

# Outside the loop (initialise once)
history = []

# Inside the loop, after reading sensor:
history.append((temp, hum, label))
if len(history) > 5:
    history.pop(0)  # Remove oldest

Troubleshooting Reference

Common problems and solutions — print this for student desks

ProblemLikely causeFix
Web page won't load on phone Phone on different WiFi, or IP has changed Check phone is on same WiFi as Pico. Rerun code and read the new IP from Thonny Shell.
Thonny says "No device" Wrong interpreter selected, or USB cable issue Tools → Options → Interpreter → MicroPython (Raspberry Pi Pico). Try a different USB cable (some are charge-only).
Sensor reads -999 or crashes Loose wire, or sensor read too frequently DHT22 needs 2 seconds between reads minimum. Check GP13 wire is firmly in the right hole. The try/except block should catch the crash — confirm it is there.
Buzzer keeps buzzing constantly Missing buzzer.value(0) after the beep Ensure you have buzzer.value(0) after time.sleep(0.3) in your buzzer block. Also add buzzer.value(0) in the except block.
Button always reads 1 (stuck) Pull-down resistor missing or wired incorrectly Confirm 10kΩ from GP14 to GND. Pin should read 0 when not pressed, 1 when pressed to 3.3V.
SyntaxError in f-string Curly braces in HTML not escaped In f-strings, literal { and } in CSS must be doubled: {{ and }}. Variable substitutions stay single: {temp}
Pico freezes after a while Memory leak or unhandled exception Add import gc; gc.collect() at the start of each loop iteration to run garbage collection. The try/except block should prevent full crashes.
WiFi connects but drops out Distance from router, or AP interference Move Pico closer to router. Add a WiFi reconnect check: if not wlan.isconnected(): wlan.connect(ssid, password) at the top of the loop.
