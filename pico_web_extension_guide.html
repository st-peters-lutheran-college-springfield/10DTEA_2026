The only part of the code you need to change is the HTML inside the web_page() function. Everything else stays the same.

🔍 Finding the HTML in your code

Your Python file has a function called web_page(). The HTML lives inside the triple-quoted string — between the return f""" and the closing """. This is the only section you are editing today.

Important rule

Do not change anything above or below the web_page() function unless you are on the extension pathway. Only edit the HTML inside the function.

Add after your existing hardware setup lines 
from machine import PWM

buzzer = PWM(Pin(15))

def alert_beep():
    # Short double-beep to signal alert
    for _ in range(2):
        buzzer.freq(1000)
        buzzer.duty_u16(30000)
        time.sleep(0.2)
        buzzer.duty_u16(0)
        time.sleep(0.1)

Calling the alert — add inside your main loop

Add inside the while True loop, after reading the sensor

    alert_beep()
🟢 Support tip

If the buzzer doesn't sound, check that the positive wire goes to GP15, not GND. Also make sure you added the from machine import PWM line — it must be at the top with your other imports.

🟣 Extension idea

Change the buzzer.freq(1000) value. Try 500 for a low tone, 2000 for a high pitch. Could you play different tones for temperature alerts vs humidity alerts?

🔘  Extension B — Physical push button ▼

Code — add to hardware setup

Add with your other hardware lines

button = Pin(14, Pin.IN, Pin.PULL_UP)

# Flag to track if alert has been silenced
alert_silenced = False

Code — read button in the main loop

Add at the start of your while True loop 
# Check if button is pressed (reads 0 when pressed with PULL_UP)
if button.value() == 0:
    alert_silenced = True
    time.sleep(0.3)  # debounce delay
🟢 Why PULL_UP?

The Pico has a built-in resistor that keeps the pin reading 1 (high) when the button isn't pressed. When you press it, the circuit connects to GND and the pin reads 0 (low). This is the most reliable way to wire a button.

Tab 5 · Common issues and fixes

Troubleshooting

Find your error message or symptom below. Most problems have a simple fix.

🔴 Python errors in Thonny

SyntaxError — invalid syntax
Usually a missing quote, bracket, or colon. Look at the line number Thonny highlights. Check that all " and ' are matched, and that any if: / def: lines end with a colon.
IndentationError
Python cares deeply about spaces. Make sure you haven't mixed tabs and spaces. In Thonny, press Ctrl+A to select all, then use Format → Fix Indentation to tidy it up.
KeyError or NameError — variable not found
A variable like comfort_msg or comfort_bg is used before it's defined. Make sure the comfort logic block is at the TOP of the web_page() function, before the return statement.
The page shows raw HTML text instead of a formatted page
There's a problem with the f-string — likely an unmatched """. Make sure the return f""" at the start of the HTML has a matching """ at the very end of the HTML block, on its own line.

🔵 Connection issues

Shell shows "Connecting to WiFi..." but never connects
Check that ssid and password at the top of your file are exactly right — including capital letters. Also check your device and the Pico are on the same Wi-Fi network (not a 5GHz vs 2.4GHz mismatch).
Webpage won't load in the browser
Make sure you're typing http:// before the IP address — not https://. Your device must also be on the same Wi-Fi as the Pico W. Try another device (phone vs laptop) to rule out network issues.
Thonny can't see the Pico W (no MicroPython option)
Try a different USB cable — some cables are charge-only with no data wires. If the cable is fine, hold the BOOTSEL button on the Pico while plugging it in, then reinstall MicroPython firmware via Thonny → Run → Configure Interpreter.

🟡 HTML / display issues

My CSS styles aren't showing up
Remember that inside a Python f-string, CSS curly braces must be doubled: {{ and }}. Single curly braces are treated as Python variable placeholders and will cause errors or disappear.
The comfort status always shows green even when temperature is high
Make sure the if 18 <= temp <= 26 logic block is inside the web_page() function and uses the temp and hum parameters — not hard-coded numbers. Check for typos in the variable names.
The page doesn't auto-refresh
Check that your <head> section still includes: <meta http-equiv="refresh" content="5">. It may have been accidentally deleted when you replaced the head block.

🟣 Extension hardware issues

Buzzer doesn't make any sound
Check: (1) positive leg is on GP15, negative on GND. (2) from machine import PWM is at the top of the file. (3) buzzer.duty_u16(0) isn't accidentally being called right after the beep. If using an active buzzer instead of passive, just use buzzer = Pin(15, Pin.OUT) and buzzer.value(1) / buzzer.value(0).
LED doesn't light up
Check: (1) long leg (anode) goes through a 220Ω resistor to the GP pin — NOT directly. (2) short leg (cathode) goes to GND. (3) the pin number in code matches the pin number on the board. GP pin numbers are printed beside each pin on the Pico.
Still stuck?

Take a photo of your screen showing the error, and a photo of your wiring. Your teacher can send these to the DT teacher for help. Most problems can be solved remotely from a photo.
